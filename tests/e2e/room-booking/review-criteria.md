# 端到端评审标准：会议室预约

日期：2026-11-05。在任何一步生成之前写定，不提供给执行者。

链路：saan-discovery → saan-prd-writing → saan-diagram → saan-mermaid。每一步在只含该技能副本、原始材料和上游产出的隔离目录中，由全新上下文执行。评审看含义和证据，不看标题或措辞。

## C1 未决事项沿链路保留

以下事项在原始材料中没有结论。每一步都不应补成确定规则；下游应继续列为待确认，或明确不涉及。

- 会议主题长度上限
- 新预约最少提前量（行政建议 24 小时、业务建议 2 小时，无决策者）
- 改期的提前量
- 员工取消是否需要原因
- 停用会议室中既有有效预约的处理（需行政负责人确认）
- 取消记录保存期限、谁可查看取消原因
- 预约与取消的通知方式、失败重试方式
- 可提前预约的天数、每人可同时持有的预约数
- 冲突提示及其他未确认文案（只能标为建议）

## C2 已决结论不回退

- 即时占用，无审批节点；「行政审批」只作为被替代的讨论选项出现，图中不得出现审批步骤。
- 入口名「会议室」「我的预约」，状态文案「已占用」「已取消」。
- 管理员只能取消自己管理的会议室中未开始的有效预约，原因必填，不能改期他人预约。
- 校验在提交处理时执行，不只依赖前端按钮。

## C3 核心规则前后一致

左闭右开占用、半小时刻度、09:00—18:00、同日、Asia/Shanghai；并发最多一个成功；改期失败时原预约不变；改期不与自身原占用冲突；已开始的预约不可改期或取消；主题只对预约人和该会议室管理员可见；停用会议室不接受新预约或改期目标。

## C4 交接

- PRD 是否使用调研底稿：沿用其缺口、责任角色或术语，而不是忽略或照抄。
- 图中角色、分支、状态是否与 PRD 一致，有无 PRD 中没有的步骤。
- 状态图的状态集合是否与 PRD 一致；「已开始」是时间条件还是存储状态，各步说法是否一致。
- 下游发现上游的矛盾或缺口时，是指出来，还是悄悄改掉。

## C5 不编造

不凭空给出技术栈、性能或可用性指标、通知渠道、真实人员、日期承诺或评审通过结论。
