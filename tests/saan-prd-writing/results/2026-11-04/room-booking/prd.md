## 1. 引言

### 1.1 文档范围与依据

本文档定义会议室预约对象的创建、查看、改期和取消行为。本文档同时定义预约占用的判断、操作权限、主题可见范围和取消操作记录。

本文档使用以下三类标记：

- **已确认**：有 S-01 业务条件或 S-02 明确结论支持，可进入实现和验收设计。
- **本稿建议**：为评审提出的界面结构或文案，尚未形成业务决定。
- **待确认 Q-xx**：材料未确定或存在冲突，不作为已批准规则。

S-02 明确采用即时占用，替代 S-01 中的行政审批讨论选项。该替代关系只适用于审批事项。S-02 中“尚无结论的意见”不因日期较新而自动成为规则。其他不冲突的 S-01 业务条件继续适用。

本稿直接交付，未等待补充答复。未决事项集中在附录 B，各章节引用对应编号。

## 2. 项目概况

### 2.1 项目背景

一个办公点有多间会议室。员工目前在群内询问空闲情况，行政人员手工登记。不同员工可能先后看到同一空闲时段。行政完成登记前，员工无法确定最终预约结果。

本期在已有办公门户加入预约功能。员工身份和会议室资料沿用门户已有模块。会议室资料管理继续由原模块负责。

### 2.2 项目目标

| 目标 | 判断方式 | 依据 |
|---|---|---|
| 员工可查看会议室占用，并完成一次预约 | 检查查看范围、提交结果和新增占用；主题按权限展示 | S-01 条件 1、8 |
| 避免同一会议室冲突时段被并发预约成功 | 对两个相互冲突的并发提交，检查成功数及最终占用 | S-01 条件 3、4 |
| 预约人能够调整或取消符合条件的预约 | 检查权限、提交时点和改期前后占用；失败保留原记录 | S-01 条件 5—7；S-02 明确结论 |
| 管理员能够取消管理范围内符合条件的预约 | 检查管理关系、取消原因和实际操作记录 | S-01 条件 9、10 |

本稿不设定节约工时、预约成功率或使用率增长指标。材料没有这些指标的基线、目标和统计口径。

### 2.3 本期范围

| 范围 | 内容 |
|---|---|
| 本期包含 | 单办公点会议室占用查看、单次预约、「我的预约」、预约人改期与取消、管理员取消、主题权限控制、取消记录 |
| 使用既有能力 | 门户登录、员工身份、会议室名称／容量／启用状态 |
| 本期不包含 | 会议室资料管理、跨办公点预约、周期预约、参会人邀请、签到、收费、使用情况统计、审批节点 |
| 尚待确定 | 预约与取消通知、失败重试方式，见 Q-09；未明确为本期承诺 |

使用情况统计只是后续需求意向，不构成本期扩展能力或交付时间承诺。

## 3. 系统概述

### 3.1 系统应用边界

| 对象 | 责任 | 与本期的关系 |
|---|---|---|
| 员工、会议室管理员 | 在门户内发起查看、预约和符合权限的操作 | 使用本期功能 |
| 门户既有登录与员工模块 | 提供登录身份及员工身份数据 | 作为创建人及权限判断的身份来源 |
| 门户既有会议室模块 | 提供名称、容量、启用状态 | 作为展示、选择与提交校验的数据来源；本期不维护这些资料 |
| 本期预约功能 | 管理预约、占用变化、主题展示权限与取消操作记录 | 本期建设边界 |
| 会议室管理关系 | 确定管理员负责的会议室 | 业务依赖已明确，数据来源和更新方式待确认 Q-10 |

上表表示逻辑责任，不表示已确认的服务部署架构。材料没有提供数据库、中间件、技术栈或部署拓扑。

### 3.2 业务整体框架

员工由「会议室」查看占用，再填写新预约。提交处理检查身份、时间、会议室启用状态和占用条件。满足已确定条件且无冲突时，系统直接形成有效预约。材料没有确定的新预约提前量等政策仍须另行决策，见 Q-01—Q-03。

有效预约在「我的预约」中供创建人查看。创建人可对尚未开始的有效预约发起改期或取消。管理员通过其管理会议室的占用记录发起取消。

| 操作 | 业务对象变化 | 占用变化 | 规则入口 |
|---|---|---|---|
| 新预约成功 | 产生有效预约 | 目标区间形成占用 | BOOK-01—BOOK-05 |
| 改期成功 | 原预约的会议室、日期和时段更新；主题、创建人及有效状态不变 | 原占用释放，新区间生效 | MOVE-01—MOVE-04 |
| 改期失败 | 原预约保持不变 | 原占用保持，目标不生效 | MOVE-03、MOVE-04 |
| 取消成功 | 原预约变为「已取消」，记录取消操作 | 原占用释放 | CANCEL-01—CANCEL-03、ADMIN-01—ADMIN-03 |

上表是流程索引。详细判断与异常处理以第 4 章对应编号为准。

## 4. 功能需求

本章业务字段描述逻辑数据，不指定物理表结构、编码方案或接口协议。材料未提供的长度、格式和默认值不会自动取模板值。

界面尚无视觉稿。下文的区域划分、按钮名称和交互安排均为本稿建议；对应业务规则若有来源，则独立作为已确认需求。已确认的界面文字只有「会议室」「我的预约」「已占用」「已取消」。建议文案不作为精确文本验收依据。

### 4.1 会议室与预约

本模块面向登录员工。模块使用门户的会议室资料呈现占用情况，并接收一次预约的输入。查看结果帮助员工选择时段，实际能否预约由提交处理时的检查决定。

#### 4.1.1 会议室占用查看

**业务描述**

员工通过「会议室」查看所有会议室的占用时段。系统根据当前员工与预约、会议室的关系，决定是否展示会议主题。会议室管理员在占用记录中取得管理取消入口，具体操作见 4.3.1。

**界面设计**

| 界面元素 | 结构与交互建议 | 业务依据 |
|---|---|---|
| 「会议室」入口 | 使用已确认名称；进入会议室占用视图 | S-02 明确结论 |
| 会议室资料区 | 建议展示名称、容量、启用状态 | VIEW-01 |
| 日期与占用区 | 建议允许切换日期，按会议室展示时段；初始日期、默认选择与刷新方式见 Q-11 | VIEW-01、VIEW-02 |
| 占用内容 | 主题展示按 VIEW-02；无权限时显示已确认文字「已占用」 | VIEW-02 |
| 新预约入口 | 建议标签「预约」；已停用会议室不能提交新预约，控件隐藏或禁用方式见 Q-11 | BOOK-02 |
| 管理取消入口 | 建议标签「取消预约」；仅依权限决定可操作范围，具体呈现见 Q-11 | ADMIN-01 |

无占用时的图形和文字、加载失败表现均未定稿，见 Q-11、Q-13。空闲展示不等于预先占有时段。

**业务字段**

| 字段名称 | 数据类型 | 长度／格式 | 必填 | 备注 |
|---|---|---|---|---|
| 会议室引用 | 既有标识类型，待对接确认 | 沿用门户，具体格式待确认 | 作为关联必需 | 区分具体会议室；名称不替代标识 |
| 会议室名称 | 文本 | 沿用既有资料 | 展示使用，源数据完整性见 Q-10 | 只读 |
| 会议室容量 | 数值 | 单位：人；既有取值范围待确认 | 展示使用，源数据完整性见 Q-10 | 不据此增加参会人数校验 |
| 启用状态 | 状态值 | 启用／停用的接口编码待确认 | 提交校验必需 | 只读；来自既有资料 |
| 查看日期 | 日期 | 按 Asia/Shanghai 解释；显示格式待确认 | 查询条件，默认值待确认 | 不据此确定可预约日期范围 |
| 占用日期、开始时间、结束时间 | 日期及时间 | 业务范围引用 TIME-01 | 有占用记录时必需 | 来自有效预约 |
| 会议主题／占用文字 | 文本 | 主题长度待确认；占用文字为「已占用」 | 有占用记录时按权限展示 | 展示用途；不另存为业务状态 |

**功能约束**

1. **VIEW-01｜查看范围。** 登录员工可查看所有会议室的占用时段。占用来自当前有效预约；取消后的区间不继续作为该预约的占用。停用会议室已有有效预约如何处理见 Q-07，不能通过停用直接推定这些预约已取消。来源：S-01 条件 7、8、11。
2. **VIEW-02｜会议主题可见性。** 当前员工是预约创建人，或是负责该会议室的管理员时，可查看该预约主题。其他员工只看到「已占用」。普通员工权限不能因进入不同查看入口而扩大。主题不得在无权员工可获得的查看结果中泄露。主题以外的创建人、原因等数据展示范围见 Q-06、Q-11。来源：S-01 条件 8。

#### 4.1.2 新建单次预约

**业务描述**

当前登录员工选择一间会议室、一个日期、开始时间、结束时间，并填写会议主题。系统在提交处理时检查已确定的条件。符合条件且无冲突的提交直接成为有效预约，不经过行政审批。冲突或其他校验失败时，不产生成功预约。

新预约提前量存在两项冲突意见，见 Q-01。可提前预约的天数、可持有预约数量见 Q-03。上述未决项未被解释为无限制，也未被写入确定规则。

**界面设计**

| 界面元素 | 结构与交互建议 | 关联规则 |
|---|---|---|
| 预约输入区 | 建议集中呈现会议室、日期、开始时间、结束时间、会议主题 | BOOK-01、TIME-01 |
| 创建人 | 建议只读显示当前登录员工，不提供替他人选择创建人的控件 | BOOK-01 |
| 提交控件 | 建议标签「提交预约」 | BOOK-03、BOOK-04 |
| 反馈区 | 建议成功提示「预约成功」；冲突提示「该时段已被占用，请重新选择」 | BOOK-03、BOOK-04；文案待确认 Q-11 |
| 返回／关闭 | 建议标签「返回」或「关闭」；未提交内容保留规则见 Q-11 | 未形成业务规则 |

是否由占用视图预填会议室和日期、提交后停留或跳转、错误后保留哪些输入，见 Q-11。不得将建议流程作为已确认的导航行为。

**业务字段**

| 字段名称 | 数据类型 | 长度／格式 | 必填 | 备注 |
|---|---|---|---|---|
| 会议室 | 既有会议室引用 | 一次一个；标识格式待对接确认 | 是 | 用户选择；启用校验见 BOOK-02 |
| 预约日期 | 日期 | Asia/Shanghai；可选日期范围待确认 | 是 | 用户选择，一次一个日期 |
| 开始时间 | 时间 | 半小时刻度；规则见 TIME-01 | 是 | 与预约日期合成开始日期时间 |
| 结束时间 | 时间 | 半小时刻度；规则见 TIME-01 | 是 | 与同一预约日期合成结束日期时间 |
| 会议主题 | 文本 | 长度、空白处理及字符限制见 Q-04 | 是 | 用户输入；用于授权展示，不允许改期时修改 |
| 创建人 | 员工引用 | 沿用门户员工标识，格式待确认 | 系统确定，必需 | 当前登录员工；不接受代预约身份 |
| 预约业务状态 | 状态值 | 有效／已取消；物理编码未定 | 系统确定，必需 | 创建成功后有效；显示名除「已取消」外未定 |
| 预约引用 | 逻辑标识 | 标识生成与格式待设计确认 | 关联预约操作必需 | 支持后续查看、改期和取消，不要求特定主键方案 |

**功能约束**

1. **BOOK-01｜输入及归属。** 创建预约时，系统要求会议室、日期、开始时间、结束时间和会议主题。创建人取当前登录员工，不允许替他人预约。主题缺失时不得创建；主题空白字符判定见 Q-04。来源：S-01 条件 1。
2. **TIME-01｜通用预约时间规则。** 新预约及改期目标时间均按 Asia/Shanghai 解释。开始和结束必须位于同一天，均采用半小时刻度，且位于 09:00—18:00 范围内。开始时间必须早于结束时间。开始可为 09:00，结束可为 18:00；相同起止时间不合格。此规则不确定日期提前量或可预约日期范围。来源：S-01 条件 2、3、5。
3. **OCC-01｜占用冲突判定。** 对同一会议室、同一日期的两个有效预约区间 A、B，令起止时间分别为 `A.start`、`A.end`、`B.start`、`B.end`。当且仅当 `A.start < B.end` 且 `B.start < A.end` 时存在占用交集。区间采用左闭右开，因此端点相接不冲突。不同会议室不构成彼此的会议室占用冲突。已取消记录不参与占用。改期时排除该预约自己的原占用，见 MOVE-03。来源：S-01 条件 3、6、7。
4. **BOOK-02｜会议室状态。** 在新预约提交处理时，已停用会议室不接受新预约；不得因页面曾显示启用或空闲就继续创建。改期目标同样受此限制，见 MOVE-02。停用前已有预约的处置见 Q-07。来源：S-01 条件 11；S-02 提交检查结论。
5. **BOOK-03｜即时生效。** 提交处理时，系统检查输入、身份归属、TIME-01、OCC-01 和 BOOK-02。符合条件且无冲突的提交直接保存为有效预约，并形成目标区间的占用。本期没有审批节点和待审批状态。来源：S-01 条件 1—4；S-02 明确结论。
6. **BOOK-04｜并发争用。** 同一会议室中，相互冲突的两个并发提交最多有一个预约成功。失败方得到冲突反馈；失败方不产生有效预约和占用。提示文字待定。界面展示或前端按钮状态不替代提交处理时的检查。来源：S-01 条件 4；S-02 明确结论。
7. **BOOK-05｜校验失败。** 提交不符合已确认的必填、归属、时间或会议室启用条件时，系统不得形成成功预约和相应占用。多个错误同时发生时的反馈顺序、字段级提示及输入保留方式见 Q-11。来源：S-01 条件 1、2、11；S-02 明确结论。

**其他**

员工是否允许与自己的其他会议室预约时间重叠，材料未给出限制，见 Q-03。本稿的 OCC-01 只定义会议室占用冲突，不扩展为人员日程冲突。网络超时、响应丢失和重复提交的恢复方式见 Q-09。

### 4.2 我的预约

本模块通过「我的预约」提供个人预约记录查看，以及创建人对记录的改期和取消操作。改期更新原预约的占用，取消保留记录并释放占用。每次操作仍在提交处理时检查归属、开始时点和状态。

#### 4.2.1 预约记录查看

**业务描述**

员工通过「我的预约」查看自己创建的预约。已取消记录仍可查。记录提供后续操作的对象引用，但是否能够改期或取消由对应操作规则决定。

**界面设计**

| 界面元素 | 结构与交互建议 | 关联规则 |
|---|---|---|
| 「我的预约」入口 | 使用已确认名称 | S-02 明确结论 |
| 记录列表或详情 | 建议展示会议室、日期、时段、主题和业务状态 | MINE-01、VIEW-02 |
| 已取消记录 | 使用「已取消」文字；建议与其他记录通过状态区分 | MINE-01、CANCEL-02 |
| 操作区 | 建议标签「改期」「取消预约」；隐藏或禁用方式待确认 | MOVE-01、CANCEL-01 |

默认排序、分页、历史查询时段和筛选方式见 Q-11。已取消记录的保留期限见 Q-06。

**业务字段**

| 字段名称 | 数据类型 | 长度／格式 | 必填 | 备注 |
|---|---|---|---|---|
| 预约引用 | 逻辑标识 | 沿用预约对象 | 操作关联必需 | 用于定位同一条预约 |
| 创建人 | 员工引用 | 沿用预约对象 | 归属判断必需 | 与当前登录员工关联 |
| 会议室、日期、开始时间、结束时间 | 引用／日期／时间 | 沿用 4.1.2 | 记录显示必需 | 改期成功后显示当前生效值 |
| 会议主题 | 文本 | 沿用预约对象 | 记录显示使用 | 创建人依据 VIEW-02 可见 |
| 业务状态 | 状态值 | 已取消文字已确认，其他显示待确认 | 记录判断必需 | 不与「已占用」混用 |
| 取消操作资料 | 操作人引用、日期时间、原因文本 | 见 4.2.3、4.3.1 | 条件产生 | 保存要求不自动等于展示授权；见 Q-06 |

**功能约束**

1. **MINE-01｜个人记录范围。** 「我的预约」用于查询当前员工自己创建的预约。取消成功后，该记录仍可查询，并显示「已取消」；不得因为占用释放而将取消记录从个人可查记录中移除。取消记录的保存期限尚未确定。来源：S-01 条件 7。

#### 4.2.2 改期

**业务描述**

创建人选择自己尚未开始的有效预约，修改会议室、日期、开始时间和结束时间。系统在提交处理时检查操作资格和目标时段。成功后更新原预约，释放原占用并使新占用生效；失败时保留原预约。

**界面设计**

| 界面元素 | 结构与交互建议 | 关联规则 |
|---|---|---|
| 改期入口 | 建议从个人预约记录进入，标签「改期」 | MOVE-01 |
| 当前预约区 | 建议显示原会议室、日期、时段和只读主题，帮助核对修改对象 | MOVE-02 |
| 目标输入区 | 建议预填原会议室、日期和时段，允许编辑；预填行为待评审 | MOVE-02、MOVE-03 |
| 提交及反馈 | 建议标签「保存改期」；冲突反馈建议为「目标时段已被占用，原预约保持不变」 | MOVE-03、MOVE-04 |

关闭表单、放弃输入、失败后内容保留、成功后导航见 Q-11。页面中的原值可能已过时，处理依据是提交时的真实条件。

**业务字段**

| 字段名称 | 数据类型 | 长度／格式 | 必填 | 备注 |
|---|---|---|---|---|
| 原预约引用 | 逻辑标识 | 沿用已有预约 | 是 | 定位改期对象 |
| 目标会议室 | 会议室引用 | 一次一间，必须满足 MOVE-02 | 是 | 可与原会议室相同，也可不同 |
| 目标日期 | 日期 | 日期范围和提前量见 Q-02、Q-03 | 是 | 与目标开始、结束时间使用同一日 |
| 目标开始时间、目标结束时间 | 时间 | TIME-01 | 是 | 用户输入 |
| 原会议主题 | 文本 | 沿用原值 | 已存必有，本次不输入 | 不允许通过改期修改 |
| 创建人、原业务状态 | 员工引用／状态值 | 沿用原预约 | 校验必需 | 系统读取，不由改期输入覆盖 |

**功能约束**

1. **MOVE-01｜操作资格。** 只有创建人可改期自己创建、有效且尚未开始的预约。管理员身份不增加替他人改期的权限。提交处理时重新检查归属、状态和原预约开始时间；任一不符合时拒绝改期，原预约保持不变。来源：S-01 条件 5、7、9；S-02 明确结论。
2. **MOVE-02｜修改范围。** 改期只允许修改会议室、日期、开始时间和结束时间。主题和创建人保持不变。目标时间必须满足 TIME-01，目标会议室必须通过 BOOK-02 的启用检查。改期目标提前量尚无讨论结论，见 Q-02。来源：S-01 条件 5、11。
3. **MOVE-03｜目标占用检查。** 系统在提交处理时按 OCC-01 检查目标占用，并排除当前改期预约自己的原占用。若与其他有效预约冲突，本次改期失败。原会议室、日期、开始时间、结束时间和有效状态保持不变，原占用不释放。来源：S-01 条件 6；S-02 明确结论。
4. **MOVE-04｜改期结果。** 改期成功后，原预约采用新的会议室、日期和时段，原占用释放，新时段生效，预约保持有效。本次改期失败时不影响原预约。不得将仅释放原占用或仅生成目标占用的中间结果作为改期成功。本文约束业务结果，不指定事务、锁或存储技术。来源：S-01 条件 6；S-02 明确结论。

**其他**

同一预约被两个操作同时改期，或改期与取消同时提交时，操作优先级及过期提交反馈尚未确定，见 Q-08。处理方案应满足现有归属、状态、占用和失败保留原预约要求，但本稿不选择覆盖策略。

#### 4.2.3 预约人取消

**业务描述**

创建人对自己尚未开始的有效预约执行取消。取消成功后，预约显示「已取消」，占用释放，记录仍在「我的预约」中可查。员工是否填写取消原因见 Q-05。

**界面设计**

建议从个人预约记录提供「取消预约」操作。是否增加确认弹窗、确认文案及取消原因输入框，均见 Q-05、Q-11。这里的“取消预约”表示业务操作；关闭表单或放弃弹窗不等同于业务取消，具体界面交互仍待定。

**业务字段**

| 字段名称 | 数据类型 | 长度／格式 | 必填 | 备注 |
|---|---|---|---|---|
| 预约引用 | 逻辑标识 | 沿用原预约 | 是 | 取消对象 |
| 取消操作人 | 员工引用 | 沿用门户身份 | 成功取消时系统记录，必需 | 实际执行取消的当前员工，不替换预约创建人 |
| 取消操作时间 | 日期时间 | Asia/Shanghai 业务语义；存储格式、精度见 Q-06 | 成功取消时系统记录，必需 | 记录实际操作时间 |
| 取消后状态 | 状态值 | 显示「已取消」 | 成功取消时系统确定 | 原记录状态变化 |
| 员工取消原因 | 文本 | 长度、是否提供输入见 Q-05 | 待确认 | 不继承管理员原因必填规则 |

**功能约束**

1. **CANCEL-01｜预约人资格。** 创建人只能取消自己创建、有效且尚未开始的预约。系统在提交处理时检查归属、状态和开始时点。已经开始、已取消或不属于本人的预约，不允许按预约人身份取消。被拒绝的操作不改变预约及占用。来源：S-01 条件 5、7；S-02 明确结论。
2. **CANCEL-02｜取消结果。** 取消成功后，预约状态变为「已取消」，释放原会议室对应区间的占用。原记录继续按 MINE-01 可查。已取消预约不允许再次取消，也不允许改期。来源：S-01 条件 7。
3. **CANCEL-03｜取消记录。** 每次成功取消须保存实际操作人及操作时间。记录应关联被取消的预约。保存期限及查看权限尚未决定，见 Q-06。管理员成功取消时另按 ADMIN-02 保存原因。来源：S-01 条件 10。

### 4.3 会议室管理操作

本模块允许管理员处理自己负责会议室的占用。操作入口沿用「会议室」占用记录。管理员取消他人的预约与其取消本人预约使用不同的资格规则，不能把管理权限扩展为代预约或代改期能力。

#### 4.3.1 管理员取消

**业务描述**

管理员在自己负责会议室的占用记录中，选择尚未开始的有效预约并填写取消原因。提交校验通过后，系统取消预约、释放占用并记录操作。管理员操作本人创建的预约时仍按预约人规则处理。

**界面设计**

| 界面元素 | 结构与交互建议 | 关联规则 |
|---|---|---|
| 占用记录操作区 | 在会议室占用记录中提供操作，不另设代员工改期能力 | ADMIN-01、ADMIN-03 |
| 待取消信息 | 建议展示会议室、日期、时段及按 VIEW-02 授权的主题 | VIEW-02 |
| 取消原因输入区 | 管理员取消他人预约时必须填写；提示建议为「请填写取消原因」 | ADMIN-02 |
| 提交反馈 | 建议使用「确认取消」按钮及「预约已取消」成功提示 | CANCEL-02、ADMIN-02；文字待确认 |

对本人预约是否直接引导至个人操作视图，见 Q-11。无论入口如何安排，都按 ADMIN-03 判断业务身份。

**业务字段**

| 字段名称 | 数据类型 | 长度／格式 | 必填 | 备注 |
|---|---|---|---|---|
| 预约引用 | 逻辑标识 | 沿用预约对象 | 是 | 关联取消目标 |
| 目标会议室、管理关系 | 会议室／人员关系 | 来源和更新机制见 Q-10 | 管理权限判断必需 | 提交处理时使用 |
| 管理员取消原因 | 文本 | 长度、空白字符规则见 Q-04 | 管理员取消他人预约时必填 | 成功取消时保存；查看权限见 Q-06 |
| 实际操作人、操作时间 | 员工引用／日期时间 | 沿用 CANCEL-03 | 成功取消时系统记录，必需 | 记录实际管理员，不能记成预约创建人 |
| 取消后状态 | 状态值 | 「已取消」 | 成功取消时系统确定 | 原预约状态变化 |

**功能约束**

1. **ADMIN-01｜管理资格。** 管理员只能按管理权限取消其负责会议室内尚未开始的有效预约。提交处理时检查管理关系、状态和开始时点。管理范围外、已经开始或已取消的预约不得按管理权限取消，拒绝时预约和占用保持不变。来源：S-01 条件 9；S-02 明确结论。
2. **ADMIN-02｜原因与结果。** 管理员取消他人的预约时，取消原因必填。原因缺失不得取消。取消成功后执行 CANCEL-02 的状态与占用变化，按 CANCEL-03 保存实际操作人、时间，并保存原因。原因对谁可见未确定。来源：S-01 条件 9、10。
3. **ADMIN-03｜本人预约与权限边界。** 管理员本人创建的预约仍按 MOVE-01 和 CANCEL-01 等预约人规则操作。员工取消原因尚未确认，不因员工同时是管理员而直接强制管理员原因规则。管理员不能改期他人的预约，也不能修改已经开始的历史预约。来源：S-01 条件 9；S-02 明确结论及尚无结论的意见。
