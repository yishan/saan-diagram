## 发现的问题

1. **Q-07 在规则里选了答案。** `rules.js` 注释写明“按 now >= start 判断已开始，确切边界见 Q-07”，页面上也有待定块说明“示例不使用该边界”。没有场景用到这个边界，所以界面上看不到确定的结论，但代码确实选了一边。v0.1 的说明已要求待确认的规则不写成逻辑；这里属于“规则必须有一个判断才能运行”的情况，说明里没有给出写法。检查器只核对编号和文本，发现不了。
记录但不处理：「已预约」用了 success 色调，色调不在来源里；`patterns/components.md` 已规定色调属于呈现，不需要标注。执行者没有浏览器，只能用 Node 自测；确认框的组件名角标显示在按钮之后（只在打开“组件名”时可见）。

## 运行后的修改

`references/source-handling.md` 增加一条约定：已确认的规则必须对一个待定边界做出判断才能运行时，选一种理解，在规则注释和待定块里写明对应的待确认事项，并且不让任何场景落在这个边界上。这与本次执行者的做法一致，现在成为明确的写法。修改后没有再做全新上下文的重跑。
