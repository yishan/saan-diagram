Saan Diagram

把业务描述、需求文档、白板截图，转成同一套规范下的中文业务图示

统一的是约束语言，不是具体方案。

14种图示 49条校验规则 ≤3处核心色

怎么工作

写 spec，脚本出图

  1. 抽取阶段、节点、系统、连线
  2. 补齐必要信息缺失的业务事实、交付目标
  3. 从模板起步--init
  4. 精简表达保留业务事实与控制点
  5. --all 校验必须通过
  6. 亲眼看图看 PNG
  7. 交付HTML / PNG / 飞书画板
视觉语法

颜色只留给"系统"和"核心"

业务节点一律中性灰，核心色全图 ≤3 处。

节点

主线节点hub 主干、汇聚点 功能模块module 默认，中性浅灰 内部系统system · internal VI 主色 外部服务system · external 主色提亮 45% 核心业务core: true 全图 ≤3 处（F1） 重点能力special 一张图只突出一类，名称自定（如"AI 能力"）

连线

flow 业务主流程 data 数据、集成、推送 meta 配置依赖，必须带标签 emphasis 关键路径，全图只标一条
  • 只用正交折线，拐角半径 8，不画斜线
  • 标签放在线旁、不压线，也不压节点
  • 箭头末段 ≥ 24px，箭头前要看得到线

文字与网格

  • 节点名 ≤10 字，连线标签 ≤8 字；放不下就精简措辞，不缩字号
  • 中文最小 12px，不用等宽字体；等宽字体只给技术值（SHA-256）
  • 所有结构尺寸都落在 4px 网格上
  • 标题栏默认白底线框，不占颜色预算
  • 图例自动生成，只列图中实际用到的类型
  • 泳道不是必备的：只有列本身有含义时才画
选型速查

先问：你要表达的是什么

一段文字能说清的，就不画。

  1. 01架构视图业务能力全景：每个阶段有哪些模块，接哪些系统。arch
  2. 02主流程视图一条业务主流程怎么走，判断点在哪里分叉、回退到哪里。flow
  3. 03路径对比视图同一套阶段上，几种方式各走过哪些阶段、跳过哪些。paths
  4. 04泳道图多个角色之间谁在什么时候做什么、在哪里交接。swim
  5. 05数据流图数据从哪来、经过哪些处理、存到哪、流向谁。dfd
  6. 06审计流程图付款审批中有哪些单据、关键控制点在哪、各防什么风险。audit
  7. 07机会流程图流程里哪些环节不增值，最该砍的是哪几步。opportunity
  8. 08分层架构图平台由哪些层组成、对外接什么、受哪些体系约束。layers
  9. 09实体关系图有哪些业务对象、彼此什么关系、几对几。er
  10. 10组织架构图 + 数据隔离谁管谁之外，谁能看到谁的数据。org
  11. 11鱼骨图一个结果背后有哪些原因，哪些已经验证。fishbone
  12. 12里程碑时间线关键节点什么时候到、现在走到哪、偏了多少。timeline
  13. 13四象限图一组事项在两个维度上，该先做哪个。quadrant
  14. 14IDEF0 功能模型每个活动受什么约束、靠谁完成、产出什么。idef0

不画：时序图、状态图、物理表结构、甘特图。

架构视图

stages--init arch
回答的问题
业务能力全景：每个阶段有哪些模块，接哪些系统。
画法要点
主干节点同一行；系统块按内外部归属分深浅；scope 叠加层标出"二期建设"。

02

主流程视图

stages · paths--init flow
回答的问题
一条业务主流程怎么走，判断点在哪里分叉、回退到哪里。
画法要点
单条流程默认不画泳道，节点按固定步长等距排；判断菱形的出线标"是 / 否"。
spec · 2-flow.yaml
# 主流程视图：单条流程，默认不画泳道（列只是排版网格），节点等距排列
title: 采购业务主流程
desc: 一次采购从提交需求、预算判断、寻源评标到合同签订与付款的主流程，含预算不足的回退分支。
columns:
  - {id: f, lanes: 9}
paths:
  row: 0.6
  edge_kind: flow
  rows:
    - name: 主流程
      height: 2
      steps:
        - {label: 提交需求, col: f, lane: 0}
        - {id: budget, label: 预算充足？, kind: decision, col: f, lane: 1.5}
        - {label: 选择方式, col: f, lane: 3, in_label: 是}
        - {label: 开标评标, col: f, lane: 4.5, core: true}
        - {label: 签订合同, col: f, lane: 6}
        - {label: 验收付款, kind: hub, col: f, lane: 7.5}
        - {label: 调整预算, col: f, lane: 1.5, drow: 1.6, break: true}
  edges:
    - {from: 主流程.budget, to: 主流程.调整预算, kind: flow, route: v, label: 否}
    - {from: 主流程.调整预算, to: 主流程.提交需求, kind: return, route: hv, label: 重新提交}

# 路径验证：每一步都能从起点到达、都能走到终点；付款前必经开标评标
verify:
  must_pass:
    - {before: 主流程.验收付款, through: [主流程.开标评标]}

泳道图

stages--init swim
回答的问题
多个角色之间谁在什么时候做什么、在哪里交接。
画法要点
列就是"谁来做"，节点自上而下按时间排；回退用 U 形绕行，不压主线。

  - {id: buy,    label: 采购部门, lanes: 1}
  - {id: vendor, label: 供应商, lanes: 1}
  - {id: expert, label: 评审专家, lanes: 1}
  - {id: fin,    label: 财务部门, lanes: 1}
nodes:
  - {label: 提交需求, col: dept, row: 0.4}
  - {label: 审核立项, kind: hub, col: buy, row: 2.0}
  - {label: 发布公告, col: buy, row: 3.6}
  - {label: 投标报价, col: vendor, row: 5.2}
  - {label: 评审打分, col: expert, row: 6.8, core: true}
  - {id: ok, label: 结果有效？, kind: decision, col: buy, row: 8.4}
