Saan Diagram

v1.5.1

把一段业务说明、一份需求文档或一张白板截图，整理成结构清楚、方便修改的业务图。

梳理系统有哪些功能，可以画架构图；讨论一件事由谁接手，可以画泳道图。技能会根据要说明的问题选择图型，整理内容并检查排版。之后需要增删步骤或调整关系，可以继续修改源文件，再导出图片或写入飞书画板。

准备材料
业务描述、需求文档、白板截图
得到什么
图示源文件、网页（HTML）、图片（SVG、PNG）或飞书画板
会检查
文字与连线排版，以及流程是否遗漏或绕过必要步骤
需用其他工具
时序图、状态图、甘特图、物理表结构
安装图示类型示例检查项目保存与修改

安装

  1. 安装技能

    npx skills add yishan/saankits --skill saan-diagram

    默认只在当前项目中安装，安装时选择使用它的 AI 助手。希望其他项目也能使用时，加 -g；加 -a claude-code 或 -a codex 可直接指定助手。

  2. 需要的软件

    • 检查图示并导出网页或矢量图：Python 3.9+ 和 uv
    • 导出 PNG：本机 Chrome、Chromium、Edge 或 Brave
    • 写入飞书画板：已登录的飞书命令行工具 lark-cli 和 Node.js

  3. 直接说要什么

    • “把这份需求画成架构图，外部系统放在右侧。”
    • “画一张采购流程的泳道图，写入这个飞书画板。”

图示类型

想说明系统包含什么，先看架构图；想说明事情怎样完成，先看流程图。需要比较方案、分析原因或查看进度时，再选下面对应的图型。

架构图说明有哪些功能，以及功能之间的关系

  1. 架构视图业务能力全景：每个阶段有哪些模块，接哪些系统。
  2. 分层架构图平台由哪些层组成、对外接什么、受哪些体系约束。

流程图说明处理顺序；需要区分负责人时，用泳道分列

  1. 主流程视图一条业务主流程怎么走，判断点在哪里分叉、回退到哪里。
  2. 泳道图多个角色之间谁在什么时候做什么、在哪里交接。
  3. 总览流程图从上游系统到平台再到下游系统，业务怎么走。
  4. 审计流程图付款审批中有哪些单据、关键控制点在哪、各防什么风险。
  5. 机会流程图区分直接产生业务价值的步骤与等待、重复处理等步骤，寻找可以简化的地方。

其他图示比较方式、数据、组织、原因、优先级和进度

  1. 路径对比视图同一套阶段上，几种方式各走过哪些阶段、跳过哪些。
  2. IDEF0 功能模型每个活动受什么约束、靠谁完成、产出什么。
  3. 数据流图数据从哪来、经过哪些处理、存到哪、流向谁。
  4. 实体关系图有哪些业务对象，以及对象之间是一对一、一对多还是多对多。
  5. 组织架构图 + 数据隔离谁管谁之外，谁能看到谁的数据。
  6. 鱼骨图一个结果背后有哪些原因，哪些已经验证。
  7. 四象限图一组事项在两个维度上，该先做哪个。
  8. 里程碑时间线关键节点什么时候到、现在走到哪、偏了多少。

时序图、状态图、甘特图使用 Saan Mermaid。物理表结构不在本技能范围内。

  • 标题栏默认无边框，不计入高亮颜色的使用限制
  • 图例自动生成，只列图中实际用到的类型
  • 泳道不是必备的：只有列本身有含义时才画

导出与飞书画板

写入飞书画板

  • 先看现有内容写入前先读取画板，避免覆盖已有工作。
  • 覆盖需确认替换画板内容前，需要你明确同意。
  • 风险需确认遇到需要确认的高风险操作时，会先停下说明。
  • 指定画板只写入你提供的画板，不会另建一个。
  • 避免重复写入相同画板、写入方式和内容使用同一操作标识，供重试时核对。
  • 核对写入结果写入后重新读取画板。读取失败时，只重试核对。
脚本与返回码

画板写入统一通过 wb_publish.py。返回码 20 表示需先导出并查看现有画板，10 表示有高风险操作需确认，21 表示写入后的读取核对失败。同一目标、方式和内容会生成相同的操作标识（token），重试时复用。

保留源文件，方便下次修改

  • 导出记录保存在 *.result.json，可查看各文件是否生成成功；PNG 导出失败时会返回错误码 4。
  • 换方向：--orient vertical（阶段类图示）
  • 换品牌色：--brand "#RRGGBB"；换标题栏：--titlebar plain|outline|gray|brand|dark
