Saan X-Ray

v0.1.0

Understand what an existing system or codebase actually does today—in plain product language, before you redesign or extend it.

Point it at a running application (via browser or Computer Use), a repository, or UI screenshots. Instead of dumping a raw file tree, it delivers a scannable System Overview Briefing first, then drills into module-level fields, validation rules, and state transitions on demand.

Overview first, deep dive on demand

Pass 1: System Overview Briefing

The default first output explains the whole project in a few minutes without drowning you in framework boilerplate:

  1. System identity and inspected scope
  2. Roles and portals (at most 4 groups)
  3. Module and capability map (Module → Function, at most 6 modules)
  4. Top 2–4 end-to-end user journeys
  5. Core business objects and confirmed state lifecycles
  6. UI vs. code discrepancies and blind spots

Pass 2: As-Is Module Specification

When you pick a module or flow to inspect in detail, Pass 2 extracts a specification aligned with Saan PRD Writing:

  1. Screen regions, filters, columns, and form fields
  2. Validation rules, boundary conditions, and error messages
  3. Centralized state transition table (current state × trigger/actor/condition → target state)
  4. Unresolved questions ready for a change or specification PRD

Inspect live UI, code, or both safely

  • Live UI (Browser / Computer Use): Defaults to Observe-only mode—navigates menus, tabs, list filters, and read-only modals without clicking Save, Submit, Delete, Approve, Pay, or Send. Switches to Sandbox / Test-walk only when you confirm a test environment and test account.
  • Codebase & API schemas: Reads routes, domain models, status enums, permission guards, and background jobs, translating them into user-visible capabilities and business rules.
  • Hybrid cross-check: Compares what the interface shows against what the code implements to uncover hidden features behind flags, dead UI buttons, and terminology drift between UI labels and database enums.

Catch what screenshots or code alone would miss

Fictional evaluation case · Legacy expense claim system

“We inherited this expense portal with no docs. Walk the employee workbench in Observe-only mode alongside server.py and brief us on how claims actually work.”
  1. Hidden secondary approval: The employee UI status filter lists 6 states, but server.py defines a 7th state (MANAGER_OK) triggered when a claim exceeds 5,000 CNY and routed to the CFO.
  2. Dead UI affordance vs. hidden cron: The toolbar’s Export PDF button is an unwired stub (onclick="return false;"), while a nightly 02:00 job silently archives NEEDS_RECEIPT claims untouched for 14 days.
  3. Pass 2 baseline: Drilling into “My Claims” extracts the 7-state transition table, field validation order, and 6 open questions ready for Saan PRD Writing.

Evaluation fixtures and two-pass transcripts are kept in tests/saan-xray/ in the repository.

Keep observed facts distinct from guesses

TagMeaningHow it is handled
[Observed-UI]Seen directly on a live screen, DOM state, or screenshotRecorded as confirmed interface behavior with screen or route citation
[Observed-Code]Verified in routes, models, validators, or background jobsTranslated into business language with file or endpoint citation
[Inferred]Deduced from partial clues (such as an untriggered status in a filter dropdown)Kept separate from confirmed rules with a verification step
[Unobserved]Requires another role account, backend access, or offline policy checkListed explicitly in the blind-spot summary

Where it fits in Saan Kits

Start with Saan X-Ray when an existing system or repository is the source of truth you need to understand first. Then hand off its outputs to the rest of the kit:

  • To Saan PRD Writing: Use the Pass 2 As-Is module spec and state table as the baseline for a scoped feature change or v2 specification.
  • To Saan Diagram or Saan Mermaid: Render the discovered module map, cross-role swimlane, ER model, or state machine.
  • To Saan Discovery: Turn [Inferred] and [Unobserved] business rules into a stakeholder interview checklist.

Get started

Install Saan X-Ray from Saan Kits:

npx skills add yishan/saankits --skill saan-xray

Ask for a System Overview Briefing first:

Use saan-xray to inspect this project (and walk the staging UI in Observe-only mode if available). Give me a System Overview Briefing first: what it does, roles, module map, core user journeys, business objects and states, and blind spots.

The skill package is text-only and uses your agent’s existing file, browser, or Computer Use tools.
