Saan Mermaid

v1.2.1

Add a diagram you can update along with your document, and check for missing steps in the process.

Mermaid describes a diagram in text, so it fits naturally into Markdown, READMEs, and design documents. Bring process notes, or ask for a diagram of system interactions, record states, or a schedule. For an approval review, add the requirements the process must follow to check for bypassed reviews and missing return paths.

Bring
Process material, policies, or an existing workflow
Outputs
Editable Mermaid code and the issues found during checks
Checks
Scripts flag unreachable paths, control bypasses, and missing returns
Use another tool for
Precise presentation layouts, IDEF0, or organization/data-isolation diagrams

Installation

  1. Install the skill

    npx skills add yishan/saankits --skill saan-mermaid

    Installs into the current project and prompts for a target agent. Add -g for a user-level installation. Use -a claude-code or -a codex to select an agent directly.

  2. Prepare the environment

    • Process review: Python 3, standard library only
    • Render images: npm install -g @mermaid-js/mermaid-cli, version 12 or later required

  3. Describe what you need

    • “Review this payment process and policy for paths that bypass finance review.”
    • “Draw a sequence diagram showing how settlement records reach the finance system.”

Diagram types

Decide whether to show what exists or how work flows, then choose a diagram for the question. Use prose when it is sufficient.

Architecture diagramsShow what exists: nodes represent capabilities or functions

  • Architecture · by stageModules at each stage and the systems they connect to.
  • Architecture · by layerThe layers that make up the platform.

Process diagramsShow how work flows: nodes are business actions; swimlanes organize the columns

  • Process diagramThe process path, decisions, and returns.
  • Process · swimlanesHandoffs between roles.
  • Process · overviewThe end-to-end business flow across systems.

Other diagramsSequences, states, objects, schedules, priorities, and causes

  • Sequence diagramThe order of system interactions and their failure paths.
  • State diagramRecord states and the actions that trigger transitions.
  • Entity relationship diagramBusiness objects and their cardinalities.
  • Gantt chartTask schedules and dependencies.
  • TimelineWhen key milestones occur.
  • Quadrant chartPriorities across two dimensions.
  • Fishbone diagramCauses that may explain an outcome.

Architecture · by stage

%% saan: arch
flowchart LR
  classDef external fill:#8FB0FF,stroke:#8FB0FF,color:#1F2329
  subgraph contract[合同阶段]
    direction TB
    c1[合同台账]
    c2[合同变更]
  end
  subgraph settle[结算阶段]
    direction TB
    s1[产值结算]
    s2[支付管理]
  end
  subgraph ext[外部系统]
    direction TB
    fin[财务系统]:::external
  end
  contract --> settle
  s2 --> fin

Nodes represent capabilities. Draw only stage-to-stage and external-system connections.

Process diagram

%% saan: approval
flowchart LR
  classDef core fill:#E2EBFF,stroke:#2B5FD8,color:#1F2329
  apply[提交申请] --> check{审核通过?}
  check -->|是| sign[签订合同]:::core
  check -->|否| fix[退回修改]
  fix -.-> apply
  sign --> archive[合同归档]

With saan: approval, missing decisions and returns are detected. Use dashed return lines. Switch to a vertical layout for larger flows.

Process · swimlanes

%% saan: approval
swimlane-beta LR
  subgraph biz[业务部门]
    apply[发起付款申请]
    fix[修改申请]
  end
  subgraph fin[财务部门]
    audit{审核单据}
    pay[执行付款]
  end
  apply --> audit
  audit -->|通过| pay
  audit -->|退回| fix
  fix -.-> apply

Requires Mermaid 12. Lanes align, but routing and spacing cannot be controlled precisely. Lanes also establish responsibility for duty-separation checks.

Gantt chart

gantt
  title 上线计划（示例）
  dateFormat YYYY-MM-DD
  axisFormat %m-%d
  todayMarker off
  section 准备
  需求确认 :done, a1, 2026-09-01, 15d
  方案评审 :done, a2, after a1, 7d
  section 实施
  开发 :a3, after a2, 30d
  联调测试 :a4, after a3, 14d
  上线 :milestone, m1, after a4, 0d

Use after for dependencies. Changing a task duration shifts subsequent tasks automatically.

Process review

List what the process must do, such as “finance must review every payment before it is made.” This is the control checklist. Use a checklist you supply where possible. If the checklist and diagram come from the same material, the review explains that both may share the same omissions.

source: user
control: 财务复核

Drawing rules

Modeling conventions

  • Include only source-supported content; state assumptions outside the diagram.
  • Add a decision node only for a real branch.
  • Overview diagrams show the forward main path. Approval and audit flows retain decisions and returns so control risks remain visible.
  • Omit internal-role lanes when handoffs are not the focus.
  • Use solid lines by default; reserve dashed lines for returns or optional paths.
  • Highlight at most three core nodes.
  • Aim for about 15 nodes in one process diagram; split larger flows into an overview and details.
  • Keep node labels short and put feature lists in the surrounding prose.

Common syntax errors

  • Quote labels containing punctuation or parentheses: A["Contract (draft)"]
  • Use English node IDs and place localized text inside labels: apply[Submit request]
  • Do not use lowercase end as a node ID.
  • For vertical ordering within a group, use direction TB.
  • For a line break in flowchart labels, use <br/>.
  • In sequence-diagram messages, avoid : and ;.

Delivery checks

The script checks error placeholders and diagram width, warning above 1200 px. Automatic layouts can become crowded, so inspect every rendered diagram.

mmdc -i diagram.mmd -o diagram.svg -b white -q
python3 check_mermaid.py --controls controls.txt diagram.mmd diagram.svg
  1. ReadableEvery label is legible and free from overlap.
  2. DirectionalThe main flow follows one direction and avoids unnecessary crossings.
  3. CompleteRequired decisions and returns are present.
  4. GroundedEvery node and connection comes from a source or an explicit assumption.

If one or two adjustments leave the diagram tangled, split it. Use Saan Diagram when precise placement is needed.

Compatibility and limits

Swimlanes require Mermaid 12

swimlane-beta aligns lanes, but does not separate them visually, and edges may route outside. Older platforms fall back to groups whose columns do not align.

Platform versions differ

Each platform bundles a different Mermaid version. These images were rendered with Mermaid CLI 12.2 and have not been tested inside GitHub or Feishu documents.

Use the checks alongside business judgment

Checks use the diagram structure, stated requirements, and built-in rules. They cannot establish whether the real business process is sound. A diagram and checklist based on the same understanding may share omissions. Each diagram type has different checks; passing them does not verify the business.

What the drawing comparison found

In one small blind comparison, drawings made with the skill did not outscore those made without it. That comparison did not show better drawing quality. Process checks serve a separate purpose.

Beta types carry the most compatibility risk

swimlane-beta, block-beta and ishikawa-beta may not render in older versions. Prefer stable diagram types for documents that travel across platforms.
