Saan Prototype

v0.1.0

Turn the key steps in your requirements into a prototype your team can try before development.

Open the prototype and try another role or scenario. See who can take an action, what changes when it succeeds, and what the screen shows when it fails. Open decisions and proposed wording are marked where they matter, so the team can discuss them on the page.

Use for
Reviewing interactions and business rules before development
Outputs
One HTML file that opens offline, editable source files, and a table linking the prototype to its requirements
Bring
A requirements document (PRD), a feature description, or screenshots

Try borrowing a projector

This example is in Chinese. Choose 「投影仪可借」 (projector available) and click 「借用」 (Borrow). Then try the same button in 「投影仪已被乙借出」 (already borrowed by employee B). Turn on annotations to see the open question about borrowing periods and overdue equipment.

Sample data is fictional. Open the example on its own.

What to prepare and what you get

Agree on what to review

The skill reads how users reach each page, what each role can do, when actions are allowed, and which cases need testing. It lists the proposed pages, roles, and scenarios so you can adjust the scope. If you bring a short description or screenshots, it lists its assumptions and marks interface wording as proposed.

Keep the files for the next review

  • Open prototype.html in a browser. One file is enough to run the review.
  • Edit the page, rule, or scenario files and rebuild the HTML when something changes.
  • Use trace.md to find the requirements behind a page or scenario and see why any open questions were left out.

Try a booking rule in the prototype

Room booking · Validation example

Rule FR-C04 prevents overlapping active bookings for the same room. The next booking can start as soon as the previous one ends.

The scenario starts with A's weekly meeting in room A from 09:00 to 10:00. As employee B, try the three bookings from AC-02, AC-03, and AC-04.

  1. Room A, 10:00–11:00. The booking starts after the meeting and succeeds.
  2. Room A, 09:30–10:30. The booking overlaps the meeting and is rejected. A keeps the existing booking.
  3. Room B, 09:00–10:00. The booking succeeds because it is for a different room.

The conflict message is marked as proposed. Open its annotation to read question Q-12 about the wording.

To verify that only one booking succeeds when two people submit at the same time (FR-C05), test in a system that handles concurrent submissions.

What reviewers can do

  • Switch scenarios to reset the data and set the time for that case. For instance, try cancelling the same booking before and after it starts.
  • Switch roles to compare what each person can see and do on the same page.
  • Turn on annotations to see proposed wording, open questions, and the rules behind each action. Turn them off to focus on the flow.
  • Choose a neutral, blue, or dark theme for the review.

What to check before sharing

The prototype simulates confirmed rules. Open decisions appear on the relevant screen or are listed in trace.md with a reason for leaving them out. Links added just to connect pages are marked as proposals.

The automatic checks flag mismatched requirement IDs, acceptance cases that the prototype does not cover, and requests for outside resources in the page code. Try each scenario in a browser to check what the interactions actually do.

The repository records two trials each for the room-booking requirements and for a short feature description. All four met the review criteria set in advance. Later fixes were checked with automated tests and in the browser. Usability with real users remains untested.

How it fits with the other skills

Use Saan PRD Writing to write the rules and acceptance cases if the requirements need more detail. Then use the prototype to try those actions. If the review also needs a map of systems or handoffs between roles, add a diagram with Saan Diagram or Saan Mermaid.

Get started

Install Saan Prototype on its own.

npx skills add yishan/saankits --skill saan-prototype

After installing, give the requirements to your AI assistant.

Use saan-prototype to build a review prototype from prd.md. List the pages, roles, and scenarios first, then mark open questions where they affect the interface.

Building and checking the prototype requires Python 3 and its standard library. Reviewers can open the HTML file in a browser.
