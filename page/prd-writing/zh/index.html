Saan PRD Writing

把需求与原型写成可供评审的规格，说明谁在什么条件下做什么，以及数据怎样变化。

适用
完整 PRD、局部变更与既有文档修订
交付
功能规则、业务字段、验收与待确认项
依赖
文本技能，模板与示例随包提供

先说明整体，再展开功能

完整需求规格说明书

  1. 引言：范围、读者、术语与来源
  2. 项目概况：背景、问题与目标
  3. 系统概述：边界、流程与功能清单
  4. 功能需求：模块与功能详情
  5. 非功能需求：质量要求与验证条件
  6. 总体设计约束：已确认的外部限制

每个功能按同一逻辑展开

  1. 业务描述：角色、场景与业务结果
  2. 界面设计：入口、区域与交互
  3. 业务字段：类型、格式、必填与用途
  4. 功能约束：条件、处理、状态与反馈

局部变更只保留相关内容，引用项目基线。需要补充的信息再列入「其他」。

把一句要求展开成可检查的行为

虚构示例 · 采购申请批量归档

“自己创建且已完成的申请可以批量归档。选中任意不符合条件的记录时，整批中止。”
  1. 触发：采购专员选中申请，发起批量归档。
  2. 校验：全部选中申请均由本人创建，且状态为「已完成」。
  3. 结果：任意一条不符合条件时，整批中止，所有记录保持原状。
  4. 验收：选中一条他人创建的申请，检查整批记录均未改变。

处理过程中发生系统错误时，是否整批回滚仍需另行确认。校验失败的规则没有定义这一结果。

让规则、建议和未知项各有位置

  • 一个规则只有一处权威表述，界面、字段和验收引用同一编号。
  • 状态、列表分组、展示标签和操作权限分别说明。
  • 来源相互冲突时，保留双方依据及需要作出的决定。
  • 模板不预设性能数值、安全等级、技术架构或服务承诺。
  • 建议文案和未定规则保持可辨认，验收只依据已确认要求。

两种模板，一个完整写作示例

资源适用情况包含内容
完整规格 · 中英文新项目或完整评审六章正文、文档控制、验收与待确认项
局部变更 · 中英文已有项目中的一个需求变更范围、功能详情、基线影响与验收
采购申请批量归档参考具体表达粒度虚构输入、规则、状态变化与未知项处理

独立试写另用「会议室预约与改期」需求，检查相邻时段、并发冲突、改期失败保留原预约，以及未决规则的处理。验证材料保留在仓库中。

原型读取能力取决于环境中的解析工具或导出文件。技能包不含通用 .rp 解析器；Word、PDF 排版可按交付需要使用对应工具。

开始使用

从 Saan Kits 单独安装 PRD Writing：

npx skills add yishan/saankits --skill saan-prd-writing

把需求简报、评审记录或可读取的原型交给 Agent：

用 saan-prd-writing，把这些材料整理成中文需求规格说明书。先交付草稿，写清功能、字段、状态变化和验收检查，未决事项集中列出。

文档检查与模拟试写不代表实际业务验收。远程安装和在线页面以已发布版本为准。
