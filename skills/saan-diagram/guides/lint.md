# 校验规则与修法

> 用 `uv run scripts/render.py --guide lint` 输出本文；起步模板用 `--init <示例名>`。

## 两类规则

| 类别 | 编号 | 处理 |
|---|---|---|
| **排版类** | 除下一行以外的全部 | 改 spec 直到通过。`--all` 失败时会在每条后面给出修法 |
| **业务发现类** | ID1 ID2 DF1 DF2 DF3 AU1 AU2 O1 O2 Q3 C1 P1–P5 | **不许为了通过而改图**。它报的是业务问题（失控点、绕过控制、数据黑洞、权限交叉……），要原样报告用户。用户确认现状如此后，写进 spec 的 `accept`，图例下方会如实写出"已确认的发现" |

```yaml
accept:
  - {code: P1, match: 紧急付款, note: 紧急付款经总经理书面特批，事后补审}   # match 是报错信息里的片段，可省略
```

`accept` 只能确认业务发现类；写排版类编号会直接报错（ACC）。退出码：0 通过 · 1 有排版问题 · 2 只剩未确认的业务发现 · 3 spec 写错。

## 建模约束与 lint 编号

| 编号 | 规则 |
|---|---|
| **R1** | `type: process` 分组要标 main；跨组的 `flow` 只挂在 main 上 |
| **R2** | 节点放在哪个阶段，看它服务哪个阶段，不看它属于哪个系统（泳道图里看谁执行） |
| **R3** | 系统块不放进分组，只在分组外用点线接入 |
| **R4** | 系统节点必须声明 `owner` |
| **R5** | 重点能力：声明了 `special.prefix`（旧写法 `kind: ai` 默认为 "AI"）时，标签以它开头 |
| **R6** | 路径行只能沿阶段向前推进 |
| **E3** | `meta` 连线必须带标签 |
| **F1** | 核心底色 ≤ 3 处 |
| **B1** | 无框分组不能当连线端点 |
| **A1** | 箭头末段 ≥ 24px，其余段 ≥ 12px |
| **G1** | 节点（含系统块）不重叠 |
| **G2** | 连线不穿过非端点节点 |
| **G3** | 两条连线不叠在同一条线上 |
| **G4** | 可见分组（有框或底色）不交叠 |
| **G5** | auto 走线最多折一次（显式 `route`、`mid_x` / `mid_row` 不查） |
| **L1 / L2 / L3** | 连线标签 ≤8 字，不压住节点，标签之间也不互相重叠 |
| **T1** | 节点名 ≤10 字；分层图条目、实体字段要放得进自己的格子（不缩字号） |
| **S1** | 副标签不写中文 |
| **D1** | 单个阶段的节点数 ≤ 泳道数 × 12；分层图单个区块 ≤12 个条目。超出就拆成"全景 + 子图" |
| **D2** | 分层图 ≤6 层；实体关系图 ≤8 个实体；组织架构图 ≤24 个组织、≤4 层；鱼骨图 ≤6 个大类；时间线 ≤15 个里程碑、≤8 个阶段；四象限 ≤20 个事项；IDEF0 3–6 个活动（ID3） |
| **V1** | 竖排文字（贯穿栏、竖排条目）和 side 列条目要放得下 |
| **W1** | 能力链总宽不超过所在区块 |
| **K1** | 分层图 `links` 两端左右相对、间距 ≥40px |
| **F2** | 实体字段 ≤8 个 |
| **C1** | 实体关系两端都标基数 |
| **DF1–DF3** | 数据流图：数据必须经过处理才能流转；处理不能只进不出或只出不进；存储要有写有读 |
| **AU1 / AU2** | 审计流程图：控制点必须写风险；单据必须有连线 |
| **O1** | 组织架构图：两个数据域只能嵌套或并列，不能部分交叉 |
| **O2** | 数据域的框不能框住不属于它的组织 |
| **O3** | 授权要写 kind 和标签；外层域本来就能看到内层，不用再画"外→内只读" |
| **O4** | 域名要放得进自己的框 |
| **FB1** | 鱼骨图：每个大类至少有一个原因 |
| **TL1 / TL2 / TL3** | 时间线：日期要在轴的范围内；标签错行不超过 3 行；阶段开始不能晚于结束 |
| **Q1 / Q2 / Q3** | 四象限：坐标在 0–10 之内；标签要放得下；事项不能压在分界线上 |
| **ID1 / ID2** | IDEF0：每个活动至少一个控制、至少一个输出 |
| **ID5** | IDEF0：一个活动的同一侧箭头太多放不下 |
| **P1–P5** | 流程路径验证（`verify`）：控制点被绕过 / 步骤走不到 / 死路 / 判断只有一个出口 / 岗位未分离，见 `--guide verify` |

## 修复 lint

- **A1 箭头没地方**：拉开两端元素的 `row`（上下相连差 ≥1.4，进出菱形差 ≥1.6）或 `lane`；分组内用 `row_step`；U 形回线加大 `offset`；指定了 `mid_x` / `mid_row` 的，把拐点往起点挪。
- **G2 线穿节点**：先改 `mid_x` / `mid_row`，让拐点走空白泳道或阶段间缝隙。不行就用 `port_a` 换出线位置。最后才挪节点。
- **G5 折了两次**：上下相接的两个节点放同一 `lane`，左右相接的放同一 `row`；斜对角的两端拉开到能一折走通（出线方向留 ≥12px、箭头段留 ≥24px），或把挡路的节点挪开。确实需要绕行（如回退线）就显式写 `route`。
- **G3 线叠线**：给其中一条加 `mid_x` / `mid_row` 偏移 ≥12px。如果它们本来就该共用起点，用 `bus: true`。
- **G1 系统块与节点重叠**：系统块比旧版的圆宽，挪开 `lane`，或者把系统块移到对应节点正下方 / 正右方，用直线接入。
- **L2 标签压节点**：用 `label_at: start / end` 把标签挪到另一段，那一段要经过空白区域。
- **T1 / L1 字太多**：精简措辞，例如"招标/询比/谈判"改成"招标询比谈判"。**不缩字号。**
- **B1**：改连分组里的主线节点，或者确认这个框值得画，再加 `frame: true`。
- **F1**：只保留真正的核心。其余可以用 hub 表示主线，不用底色。
- **主流程穿过兄弟节点**：把主干节点挪到单独一行，细节放下方。
- **换方向后出错**：通常是 A1 或 L2。按上面的方法微调，两个方向都 PASS 后再交付。
- **分层图 T1 条目放不下**：精简措辞，或给该区块减 `cols`、加 `w`，或加大 `width`。**W1 能力链太宽**：合并阶段、减少步骤，或把能力层区块单独占满一层。**V1 竖排放不下**：贯穿栏精简到 4–6 个关注点，side 列给 section 加 `span` 或减条目。
- **L3 标签互相重叠**：多半是几条线在同一片空白里转弯。数据流图用"处理/存储交替排行 + `label_at: 1`"；其他图先删掉能从布局看出来的标签（如单据连线），再拉开行距。
- **DF1**：在两个存储或实体之间补一个处理过程（谁在搬运数据，就把谁画出来）。**DF2 / DF3**：补上漏画的输入、输出、写入或读取，或者删掉多余的节点。
- **O1 / O2**：用 `exclude` 把不该包含的子树排除出去，或者把交叉的部分拆成独立的域。**O3**：删掉多余的外→内只读授权。**O4**：缩短域名（如"A 公司数据域"），说明文字放进 desc。
- **FB1**：删掉空的大类。**TL2**：合并相邻里程碑、只留需要决策的节点，或加大 `width`。**TL1**：调整 `start` / `end`。**Q2**：把挤在一起的事项坐标微调 0.3–0.5，或缩短名称。**Q3**：把压线的事项挪到一侧，并说清理由。
- **ID1**：补上约束这个活动的制度或标准；确实找不到，就把它当成管理漏洞写进交付说明，不要编一个控制。**ID3**：把活动合并或分解成子图。**ID5 / L3**：把同类箭头合并（如多份文件合成"投标文件"），或调整 spec 里 controls / mechanisms 的顺序。
- **R5**：把标签改成以 `special.prefix` 开头；如果这张图不需要强制前缀，删掉 `prefix`。
- **AU1**：给控制点补 `risk`；说不出防什么风险的控制点，多半不是关键控制，删掉。
- **ER 的 G2 关系穿过实体**：调整 `col/row`，把关系多的实体放中间；仍然交叉就按业务域拆图。
- **原图里的穿线、错色问题不要照搬**，在交付说明里写一句"原图 X 处已按规则修正"。
