# 文字与配色

> 用 `uv run scripts/render.py --guide style` 输出本文；起步模板用 `--init <示例名>`。

## 文字
| 角色 | 字号 / 字重 | 规则 |
|---|---|---|
| 图标题 | 16px / 600 | 只写图名 |
| 阶段名 | 14px / 600 | 阶段名或角色名 |
| 节点名 | 12px / 400（hub、core 为 600，系统块为 500） | **≤10 字（T1）**；放不下就精简措辞，**不缩字号**（中文最小 12px） |
| 连线标签 | 12px / 500，次级灰 | **≤8 字（L1）**，写动作或数据名（"签发令牌""是""否"） |
| 副标签 | 9px 等宽 | 只写拉丁字符的技术值 |

中文不用等宽字体、不全大写、不加字距。等宽字体只给技术值用。

## VI 配色
spec 里只写一个主色，其余颜色都从它推导，**不在 spec 里写其他颜色**：

```yaml
brand: "#0F7B6C"      # VI 主色；不写 = 飞书蓝 #3370FF
titlebar: plain       # plain（默认，无边框）| outline（白底线框）| gray | brand | dark
```

| 用途 | 推导方式 |
|---|---|
| 内部系统块、关键路径、核心描边 | 主色 |
| 外部服务块 | 主色向白色提亮 45% |
| 核心节点底色 | 主色向白色提亮 86% |
| 核心区域底色 | 主色向白色提亮 94% |
| 系统块和标题栏上的文字 | 按 WCAG 对比度自动选白色或深色 |

业务节点、阶段线、连线始终是中性灰，不随主色变化，这样换任何 VI 都不会花。命令行 `--brand` / `--titlebar` 可以临时覆盖 spec 里的值。旧 spec 的 `theme: gray / blue` 仍然可用，等于预设主色。

## 对比度

形状和背景分不清、文字看不清，都算排版错误，`--all` 会按实际绘制结果检查（CT1 / CT2），所有图示类型都适用。

| 检查 | 要求 |
|---|---|
| 小元素（节点、条目、色块）和背景 | ≥ 1.15:1，或有 ≥ 1.3:1 的描边 |
| 大分区（里面还放了别的形状） | ≥ 1.05:1，或有描边 |
| 页面文本和背景 | > 4.51（符合 W3C WCAG AA 4.5:1 标准） |

写法上记住三条：浅底分区里的条目用白底，不要用浅灰叠浅灰；不要把同一色阶的底色叠在一起；深底配白字、浅底配深字。

主色作文字、描边或标题栏时，如果和背景达不到 > 4.51（W3C WCAG AA 4.5:1），渲染器会自动调整明度（色相不变），保证全页文本对比度达标。
