## 变更背景与范围

采购专员目前需要逐条归档已完成的采购申请，重复操作较多。本次在采购申请列表增加批量归档，覆盖归档条件判断、二次确认、状态更新和归档操作记录。

本节面向业务评审、设计、研发和测试人员。规则来源为随包提供的虚构需求输入。归档后恢复、批量数量上限以及处理中失败的处理规则尚未确认。

## 4. 功能需求

### 4.1 采购申请管理

本次调整涉及采购申请的归档环节。采购专员在列表选择申请后，系统先校验范围与状态；全部符合条件时进入确认，再由归档结果更新申请状态和记录。

### 4.1.1 批量归档

**业务描述**

采购专员需要归档已完成的采购申请时，可从列表选择多条申请发起批量归档。允许操作的数据需要同时满足：由当前用户创建，且当前状态为「已完成」。

业务顺序为：选择申请 → 校验全部申请 → 确认归档 → 归档成功后更新状态和记录。校验不通过和用户取消分别按 FR-003、FR-005 处理；系统处理失败的规则见 Q-02。

**界面设计**

本次未提供视觉稿。以下说明页面元素与交互要求，作为后续原型输入。

| 界面元素 | 展示与交互 | 关联规则 |
|---|---|---|
| 采购申请列表 | 使用现有列表选择本次归档对象；跨分页选择范围待确认。 | FR-002、Q-04 |
| 批量归档按钮 | 标签为「批量归档」；未选中记录时禁用。 | FR-001 |
| 校验反馈 | 对不满足条件的选择结果展示指定错误提示。 | FR-003 |
| 归档确认对话 | 展示本次申请数量，提供确认和取消操作；关闭对话按取消处理。 | FR-004、FR-005 |
| 归档成功反馈 | 更新列表中的申请状态，并展示成功数量。 | FR-006 |

**业务字段**

这里的“数据类型”为业务语义类型。物理字段类型、标识格式和技术存储结构尚未提供。

| 字段名称 | 数据类型 | 长度／格式 | 必填 | 备注 |
|---|---|---|---|---|
| 选中的采购申请 | 采购申请记录集合 | 单次上限与跨分页范围待确认 | 发起操作时至少选择一条 | 来自列表选择；用于逐条校验及确定本次处理对象。 |
| 创建人 | 用户信息 | 沿用既有定义，具体格式未提供 | 校验必须能够确定 | 读取采购申请现有数据，判断是否为当前用户。 |
| 当前状态 | 业务状态 | 本功能涉及「已完成」「已归档」；其他状态未展开 | 校验必须能够确定 | 读取既有状态；成功后按 FR-006 更新。 |
| 本次申请数量 n | 整数 | 选中记录条数；上限待确认 | 系统计算 | 用于确认对话；成功反馈中的 n 对应成功归档条数。 |
| 归档操作人 | 用户信息 | 具体技术格式待确认 | 归档成功时记录 | 记录实际执行归档的操作人；查看位置待确认。 |
| 归档操作时间 | 时间 | 精度与时区待确认 | 归档成功时记录 | 与归档记录关联；见 Q-03。 |

**功能约束**

| 编号 | 条件／触发 | 系统处理与结果 |
|---|---|---|
| FR-001 | 未选中采购申请 | 禁用「批量归档」按钮。 |
| FR-002 | 用户选中申请并点击批量归档 | 校验全部选中申请。每条均需由当前用户创建，且当前状态为「已完成」。 |
| FR-003 | 任意一条不满足 FR-002 | 中止整批操作，所有选中申请保持原状。提示「所选采购申请当前不可归档，请检查申请状态及操作权限」。 |
| FR-004 | 全部选中申请满足 FR-002 | 弹出确认对话，提示「确定归档选中的 n 条采购申请？」；n 为本次选中数量。 |
| FR-005 | 用户取消或关闭确认对话 | 不修改所选申请，结束本次归档操作。 |
| FR-006 | 用户确认，且归档处理成功 | 将全部选中申请变为「已归档」，记录归档操作人和操作时间，更新列表状态。提示「已归档 n 条采购申请」。 |

业务状态与结果：FR-006 成功时，「已完成」变为「已归档」；FR-003、FR-005 不改变原状态。处理中失败或确认前状态变化的结果尚未确定，不从“批量”一词推断事务处理方式。
